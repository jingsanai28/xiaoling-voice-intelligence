# 03｜上下文、Memory 与知识库

## 上下文分层

```text
当前输入：评论/客服记录/投诉/社媒反馈/图片证据
事件上下文：事实、证据、来源、风险、责任团队、复核状态
企业知识：产品知识、客服 SOP、品牌合规规则、历史案例
会话上下文：多轮追问、补证据、人工决定、任务动作
运行上下文：Agent、工具、节点、耗时、错误和 Trace
```

每一层都设有边界：当前事件优先于通用知识，知识必须已发布且有权限，历史匹配用于解释而不是直接复制结论，人工决定不能被后续模型覆盖。

## Memory 设计

Memory Match 将当前事件与历史事件库匹配，返回相似事件、历史风险、摘要和参考动作。它的目标不是让模型“记住一切”，而是让相似案例成为可引用的决策依据。

多轮对话共享同一个事件上下文，追问不会重新丢失第一轮的风险、证据和路由结果。

## RAG 知识库

知识库管理：

- 知识空间：产品知识、政策 SOP、品牌合规、历史案例；
- 文档生命周期：草稿 -> 待审核 -> 已发布 -> 已归档；
- 检索规则：只返回当前用户、当前 Agent 有权限访问的已发布文档；
- 引用契约：文档标题、版本、片段和命中原因必须可见；
- 反馈闭环：记录无命中、低相关、知识冲突和引用反馈。

## 权限设计

权限检查在路由前执行，知识检索再次执行空间和文档权限。管理员、分析人员、复核人员、知识库管理员和只读用户看到的内容与动作不同。

公开仓库只呈现权限模型和脱敏界面，不包含真实身份、密钥、客户原文或生产权限配置。
