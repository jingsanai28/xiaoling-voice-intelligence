# 04｜评测、Bad Case 与反馈迭代

## 评测资产

| 资产 | 用途 |
| --- | --- |
| 规则基线 | 验证 LangGraph 主链路、风险校准、复核和 Trace |
| 真实案例诊断集 | 发现公开/脱敏业务案例中的边界问题 |
| `Xiaoling VoiceBench` 迭代集 | 700 条，可用于规则、Prompt、路由和 RAG 迭代 |
| `Xiaoling VoiceBench` 验证集 | 300 条，锁定，不进入调参、Few-shot 或知识构造 |
| 多模型对比 | 比较 DeepSeek、豆包、通义千问、Kimi、智谱在同一任务契约下的表现 |
| Bad Case 队列 | 记录错误类型、原始输入、期望结果、修复动作和回归结果 |

公开数据集保留英文原文用于溯源，同时提供中文阅读字段。自动标签标记为银标，需要人工复核后才能作为业务金标准。

## 多 Agent 评测维度

- 降噪与高价值信号识别；
- 任务类型路由准确率；
- Agent 选择准确率；
- 风险等级校准；
- 证据充分性和建议可执行性；
- Human Review 触发准确率；
- Memory Match 命中质量；
- RAG 引用完整性与权限过滤；
- 多轮对话上下文一致性；
- Trace 完整性。

## 多模型评测如何使用

多模型对比是诊断工具，不是把分数最高的模型直接放进生产。统一输入、结构化输出和失败策略后，比较路由、风险、复核和解释等指标，再把稳定的边界交给确定性系统节点兜底。

## 同一任务契约下的真实对比

首轮对五个模型使用同一套 11 条企业反馈分诊用例、Prompt、Schema、Memory、Human Review 和报告逻辑。下面是脱敏后的汇总，重点看它如何影响系统设计，而不是把它当成通用模型排名：

| 模型 | 端到端通过率 | 路由 | 风险等级 | Schema 有效 |
| --- | ---: | ---: | ---: | ---: |
| 通义千问 | 7/11 | 80% | 100% | 100% |
| Kimi | 6/11 | 90% | 100% | 100% |
| 智谱 GLM | 4/11 | 80% | 45% | 94% |
| DeepSeek | 2/11 | 70% | 27% | 100% |
| 豆包 Seed Evolving | 2/11 | 60% | 18% | 31% |

结论是：通义千问更适合作为下一轮结构化路由候选，Kimi 需要继续收紧混合场景和报告约束，豆包需要单独的短 Prompt 与更小上下文。Risk Calibration 将模型的风险判断从不稳定输出变成可审计系统边界，所有模型仍需经过 Schema、Trace、Bad Case 和锁定验证集回归。

## Bad Case 闭环

```text
运行评测
  -> 记录错误类型与证据
  -> 判断是 Prompt、路由、知识、风险边界还是数据标签问题
  -> 只在 700 条迭代集上修改
  -> 用 300 条锁定验证集做回归
  -> 通过后更新规则、文档和版本记录
```

## 已验证的工程结果

- 规则基线：11/11 通过；
- 真实案例诊断：6/6 通过；
- 中文卡片配送路由回归：20/20；
- 评测集规模：1000 条，700/300 分层；
- 评测结果不被表述为生产准确率，公开数据和银标标签仍需人工业务复核。
