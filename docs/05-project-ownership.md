# 05｜项目职责与关键决策

## 项目角色

个人独立项目，负责产品定义、业务流程、AI 交互、Agent 架构、工程实现、评测体系和迭代闭环。

## 产品判断

- 将产品对外定位从难以理解的“风险分诊”调整为“客户声音智能分析”；
- 把风险分诊保留为底层能力，以“降噪、聚合、识别、分级、路由”组织完整价值链；
- 选择品牌舆情、客服质检和运营反馈作为三个可验证的业务场景；
- 将分析结果设计为可持续工作的事件，而不是一次性报告。

## 架构判断

- 使用 Supervisor 编排三个专业 Agent，避免单一 Prompt 同时承担不同判断标准；
- 将权限校验、风险校准、人工复核和审计下沉为系统节点，不交给模型自由裁量；
- 使用事件级共享 State 串联当前输入、证据、企业知识、历史事件和会话上下文；
- 为每个业务 Agent 定义独立工具、执行顺序和结构化输出契约；
- 对高风险场景使用 Checkpoint、Interrupt 和受控人工决定完成暂停与恢复。

## 数据与评测判断

- 建立 700 条迭代集与 300 条锁定验证集，禁止锁定集进入 Prompt、Few-shot、规则或 RAG 调优；
- 区分公开基础能力样本、真实脱敏案例、自动银标和人工金标，不把候选数据包装成业务准确率；
- 在统一契约下比较五个国产模型，用路由、风险、Schema 和端到端指标定位失败层；
- 将真实案例暴露的问题沉淀为 Prompt、路由、知识、风险边界或标签修订，并执行锁定集回归。

## 交付范围

- LangGraph Multi-Agent 工作流；
- React + TypeScript 管理端；
- SQLite 分析、会话、任务、知识和评测留存；
- RAG 知识管理与历史事件 Memory Match；
- 对话内人工复核与任务生命周期；
- Xiaoling VoiceBench、多模型评测、Bad Case 和 Trace。

## 技术栈

`LangGraph` `Python` `SQLite` `RAG` `Pydantic Schema` `LangSmith` `React` `TypeScript`
